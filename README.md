# Immortal Jellyfish Fact API

A modular FastAPI backend that returns a curated fact about the "immortal jellyfish" (Turritopsis dohrnii) with supporting and refuting sources. This repository includes the API service, tests, CI configuration, Docker assets, and Terraform for deploying to Google Cloud Run.

## Repository Layout

- immortal-jellyfish-fact-api-209930-209939/
  - inference_api_backend/ (FastAPI service)
    - src/
      - api/
        - main.py (FastAPI app with health routes and versioned API router)
        - generate_openapi.py (writes interfaces/openapi.json from the live app)
        - routers/
          - facts.py (GET /v1/facts/immortal-jellyfish)
      - core/
        - config.py (CORS configuration via env)
        - version.py (APP_VERSION exposure)
      - domain/
        - models.py (Pydantic models: Source, FactResponse, ErrorResponse)
      - services/
        - fact_service.py (business logic for fact content)
    - interfaces/
      - openapi.json (generated by generate_openapi.py)
    - tests/
      - test_health_and_facts.py (endpoint tests)
    - Dockerfile
    - requirements.txt
    - pyproject.toml, setup.cfg
  - terraform/
    - gcp/ (Cloud Run deployment)

## API Overview

The API serves a single curated fact about Turritopsis dohrnii, along with supporting and refuting sources. It exposes a health root and a health endpoint for uptime checks.

- Swagger UI: http://localhost:3001/docs
- OpenAPI JSON: http://localhost:3001/openapi.json
- Generated spec file: inference_api_backend/interfaces/openapi.json

### Endpoints

- GET / → 200 {"status":"ok"} — liveness
- GET /health → 200 {"status":"ok"} — health check
- GET /v1/facts/immortal-jellyfish → 200 FactResponse

Example response:
```
{
  "fact": "Turritopsis dohrnii can revert its mature medusa stage back to a juvenile polyp stage, allowing it to sidestep death under certain conditions. This phenomenon is sometimes described as 'biological immortality', but it does not prevent death from predation, disease, or unfavorable environments.",
  "supporting_sources": [
    {
      "title": "Reversing the life cycle: medusae reverting to polyps in Turritopsis",
      "url": "https://link.springer.com/article/10.1007/BF02391156",
      "note": "Peer-reviewed documentation of life cycle reversal (morphallaxis)."
    }
  ],
  "refuting_sources": [
    {
      "title": "No such thing as truly 'immortal' jellyfish",
      "url": "https://www.science.org/content/article/no-such-thing-immortal-jellyfish",
      "note": "Clarifies misuse of 'immortal' and real-world mortality factors."
    }
  ]
}
```

## Local Development

### Requirements
- Python 3.12
- pip

All dependencies are pinned in inference_api_backend/requirements.txt.

### Setup and Run
```
cd immortal-jellyfish-fact-api-209930-209939/inference_api_backend
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt

# Run
uvicorn src.api.main:app --host 0.0.0.0 --port 3001 --reload
```

### OpenAPI Generation
```
cd immortal-jellyfish-fact-api-209930-209939/inference_api_backend
. .venv/bin/activate
python -m src.api.generate_openapi
# Writes interfaces/openapi.json
```

### Testing
```
cd immortal-jellyfish-fact-api-209930-209939/inference_api_backend
. .venv/bin/activate
pytest -q
```

## CI

A GitHub Actions workflow exists at .github/workflows/ci.yml which installs dependencies and runs pytest. Add steps as needed for linting or packaging. The test suite validates the health endpoints and the facts endpoint structure and values.

## Docker

Build and run the image locally:
```
cd immortal-jellyfish-fact-api-209930-209939/inference_api_backend

# Build
docker build -t immortal-jellyfish-fact-api:local .

# Run (maps container 8080 to host 3001)
docker run --rm -p 3001:8080 immortal-jellyfish-fact-api:local
```

- Service will be reachable at http://localhost:3001
- Health endpoint: http://localhost:3001/health
- Swagger UI: http://localhost:3001/docs

To pass environment variables (e.g., CORS or APP_VERSION):
```
docker run --rm -p 3001:8080 -e APP_VERSION=1.0.0 -e CORS_ALLOW_ORIGINS="*" immortal-jellyfish-fact-api:local
```

## Terraform: Deploy to Google Cloud Run

Terraform configuration is in immortal-jellyfish-fact-api-209930-209939/terraform/gcp.

### Prerequisites
- Terraform >= 1.5.0
- gcloud CLI authenticated
- GCP project with billing enabled
- Enabled APIs:
  - Artifact Registry
  - Cloud Run Admin
  - IAM
- Docker installed

Enable required APIs:
```
gcloud services enable artifactregistry.googleapis.com run.googleapis.com iam.googleapis.com
```

### Build and Push Image to Artifact Registry
```
PROJECT_ID="<your-project-id>"
REGION="us-central1"
REPO_ID="app-backend"
SERVICE_NAME="immortal-jellyfish-fact-api"
IMAGE_TAG="latest"

# Configure Docker auth
gcloud auth configure-docker ${REGION}-docker.pkg.dev

# Build and push
cd immortal-jellyfish-fact-api-209930-209939/inference_api_backend
docker build -t ${REGION}-docker.pkg.dev/${PROJECT_ID}/${REPO_ID}/${SERVICE_NAME}:${IMAGE_TAG} .
docker push ${REGION}-docker.pkg.dev/${PROJECT_ID}/${REPO_ID}/${SERVICE_NAME}:${IMAGE_TAG}
```

### Deploy with Terraform
```
cd immortal-jellyfish-fact-api-209930-209939/terraform/gcp

terraform init

terraform apply \
  -var="project_id=${PROJECT_ID}" \
  -var="region=${REGION}" \
  -var="repository_id=${REPO_ID}" \
  -var="service_name=${SERVICE_NAME}" \
  -var="image_tag=${IMAGE_TAG}"
```

After apply, Terraform outputs service_url for the Cloud Run service.

To set environment variables with Terraform:
```
terraform apply -var='project_id=${PROJECT_ID}' -var='region=${REGION}' \
  -var='repository_id=${REPO_ID}' -var='service_name=${SERVICE_NAME}' \
  -var='image_tag=${IMAGE_TAG}' \
  -var='env={ APP_VERSION="1.0.0", CORS_ALLOW_ORIGINS="*" }'
```

## Configuration

CORS can be configured via env:
- CORS_ALLOW_ORIGINS
- CORS_ALLOW_METHODS
- CORS_ALLOW_HEADERS
- CORS_ALLOW_CREDENTIALS

By default, GET is allowed from all origins. The app exposes APP_VERSION via OpenAPI metadata when set.
